01 One-liner + JTBD

hy10 es el sistema operativo de citas de un solo negocio: el equipo administra servicios, staff y agendas en la web; los clientes gestionan reservas por Telegram con un agente AI conectado a la API.

Cuando un cliente quiere un turno, quiero consultar disponibilidad y reservar (o cambiar/cancelar) por Telegram sin esperar horario de oficina, para no perder la cita ni saturar al staff.

Misión

Una sola fuente de verdad para servicios, staff y agenda; un canal conversacional donde el cliente se autosirve; un agente que ejecuta acciones reales vía API.

02 Contexto y problema

Admin / Staff

Agenda dispersa, conflictos de horario, difícil saber quién presta qué servicio.

Cliente

Escribe, espera, re-explica. Fuera de horario se pierden reservas.

07 User journeys

Cliente (happy path)

Mensaje → listar servicios → slots reales vía API → confirmación → POST /reservations → confirmación Telegram.

Admin (happy path)

Login (password/Google) → dashboard → CRUD servicios → alta staff + asociación → revisión de reservas.

Edges

  • Abandono: sesión expira; no se crea reserva. Si el slot se ocupa, API rechaza y el agente ofrece alternativas.
  • Escalado: frustración / fuera de política → marcar escalated y notificar humano (Should).

08 MVP Scope (MoSCoW)

Must Should Could Won't

Must

Auth Supabase; Config global + políticas por servicio; staff N:M; agenda; reservas (elegir staff o auto); bot + agente; handoff si no puede; invitaciones; notificaciones; UI nueva; API; GHA.

Should

Historial de conversaciones; bloqueos de agenda; emails además de Telegram/in-app.

Could

Recordatorios; reportes; multi-idioma; menú explícito “humano”; WhatsApp post-MVP.

Won't

Multitenancy; pricing; web clientes; pagos; app nativa; CRM ventas; UI HiTurno tal cual.

11 Evaluación del agente

  • Dataset: 50–100 sintéticos + 20 reales del piloto.
  • Pass duro: no inventar cupos; confirmar antes de mutar; respetar políticas.
  • Red-team: prompt injection, reservar a nombre de otro, flood, slots pasados.
  • Principio: la API es la autoridad; el LLM no bypasea reglas server-side.
